# Планировщик свободного места на дисках

Демон, который переносит файлы между дисками, чтобы на «источниках» всегда
было свободное место, и который **ничего не переносит без одобрения
человека** в веб-интерфейсе.

## Как это работает

- Конфиг (`config.yaml`) перечисляет папки. У каждой — роль (`dir_type:
  src|dst`), метка (`type`) и порог свободного места (`min_free`).
- Из папки `src` переносится содержимое **уровня +1**: файл или каталог
  целиком. Ниже уровня +1 демон не смотрит, каталог переносится рекурсивно.
- Запись переносится только в папку `dst` **с тем же `type`** и только если
  она лежит на другом томе: перенос внутри одного тома места не освобождает.
- Пока на томе источника свободного места меньше `min_free`, демон строит
  план: сначала самые большие записи (так освобождается место за минимальное
  число движений).
- Запись, изменённая меньше `scan.min_age` назад, не переносится: она, скорее
  всего, ещё пишется.
- План ждёт одобрения в веб-интерфейсе. Одобрили — демон переносит; не
  одобрили — ничего не происходит.
- Каждый перенос можно **откатить** поштучно или целиком.

## Установка

```sh
make build

useradd --system --no-create-home --shell /usr/sbin/nologin diskd
install -m 0755 bin/diskd /usr/local/bin/diskd
install -d -m 0750 -o root -g diskd /etc/disk-resource-scheduler
install -m 0600 -o root -g diskd config.yaml /etc/disk-resource-scheduler/config.yaml
install -m 0644 deploy/disk-resource-scheduler.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now disk-resource-scheduler
```

Пользователю `diskd` нужны права на чтение и запись на всех медиа-томах из
конфига. Список томов в юните (`ReadWritePaths`) должен совпадать с папками
из конфига.

Конфиг читается заново, когда файл меняется: новые папки, пороги и
пользователи применяются без перезапуска. Сломанный конфиг не роняет
работающий демон — в журнале появится предупреждение, а работать он будет со
старым.

## Конфиг

Полный пример с комментариями — `config.yaml.example`. Обязательные поля:

| Поле | Смысл |
| --- | --- |
| `folders` | Папка → `dir_type`, `type`, `min_free`. `min_free` обязателен для `src` |
| `web.users` | Пользователи интерфейса: имя → пароль |
| `scan.schedule` | Cron-выражение |
| `scan.min_age` | Запись не переносится, если её mtime новее `now() - min_age` |
| `state.dir` | Где лежат план и история |
| `server.listen` | Адрес веб-интерфейса |

## Веб-интерфейс

`http://127.0.0.1:8088/` — вход по логину и паролю, таблица папок, план и
кнопки «Сканировать», «Одобрить», «Отклонить», «Убрать из плана»,
«Откатить». План обновляется сам раз в три секунды.

Файл, убранный из плана, остаётся на месте. Убрать его навсегда нельзя:
следующее сканирование может запланировать его снова.

Интерфейс слушает только loopback: пароль и cookie сессии идут по сети
открытым текстом, и тот, кто их прочитает, сможет одобрять переносы. С
другой машины — через туннель:

```sh
ssh -L 8088:127.0.0.1:8088 media-server
```

или через реверс-прокси с TLS; тогда в конфиге `base_url` должен быть
`https://...`, чтобы cookie сессии получила флаг Secure.

## API

Тот же демон с другой стороны: те же сессия и CSRF-токен.

```
GET  /api/plan          состояние, текущий план и история
GET  /api/history       законченные планы
POST /api/scan          сканировать сейчас
POST /api/plan/approve  plan_id — одобрить план
POST /api/plan/reject   plan_id — отклонить план
POST /api/plan/remove   plan_id, move_id — убрать файл из плана
POST /api/plan/rollback plan_id, move_id — откатить операцию (move_id=0 — все)
```

Значения передаются формой (`application/x-www-form-urlencoded`), CSRF-токен —
в заголовке `X-CSRF-Token` или полем `csrf_token`.

Число, которое не удалось прочитать, — это ошибка (`400`), а не ноль: ноль в
`move_id` означает «откатить всё». `POST /api/scan` отвечает `409`, если
сканирование уже идёт: библиотека обходится один раз, а не по разу на
каждый запрос.

## Где лежит состояние

- `state.json` — состояние и последний непустой план (пустой план не
  сохраняется: одобрять в нём нечего). Демон переживает перезапуск: план,
  ждущий одобрения, не теряется, а прерванная операция повторяется с чистого
  приёмника.
- `history.jsonl` — история планов, последние 50.

## Разработка

```sh
make check      # gofmt, go vet, сборка и тесты
make test       # только тесты
go test ./e2e/ -v -count=1   # сквозной тест: дерево, конфиг, демон, API
```

Сквозной тест поднимает настоящий демон на временных папках, ждёт, пока он
соберёт план, одобряет план через API и проверяет, что файлы переехали, а
после этого откатывает одну операцию.

Пайплайн (`.github/workflows/ci.yml`) делает то же самое: gofmt, `go vet`,
сборка и тесты с race detector и покрытием.

## Что демон не делает

- Не переносит ничего без одобрения.
- Не делит каталог уровня +1 между приёмниками.
- Не сохраняет hardlink'и, sparse-файлы, xattr и ACL при копировании между
  томами.
- Не переносит запись, изменённую меньше `scan.min_age` назад.
